### Task 3: R1 — array literal as the leading command word of an alias body

**Files:**
- Modify: `crates/huck-syntax/src/lexer.rs` — the alias-injection re-drive / first-body-word scan (`maybe_expand_command_alias` ~line 6584 and the `try_scan_assign_prefix` `(`-probe ~lines 5455-5467 / 5495-5507).
- Test: `crates/huck-syntax/src/lexer.rs` `#[cfg(test)]` module (or engine alias tests).

**Interfaces:**
- Consumes: `try_scan_assign_prefix` (emits `Lit "name="` + zero-width `TokenKind::ArrayOpen` when a `(` follows), `push_injection`, `maybe_expand_command_alias`.

- [ ] **Step 1: Reproduce + failing test.** Confirmed scoping (do NOT regress the working cases):

```
$ ./target/debug/huck -c 'shopt -s expand_aliases; alias foo="a=(1 2 3); echo \${a[@]}"; foo'   # huck: syntax error: unsupported command; bash: 1 2 3
$ ./target/debug/huck -c 'eval "a=(1 2 3); echo \${a[@]}"'                                        # WORKS (1 2 3) — keep working
$ ./target/debug/huck -c 'shopt -s expand_aliases; alias foo="echo x; a=(1 2)"; foo; echo \${a[@]}' # WORKS — keep working
```

Add a test asserting the leading-array alias body expands and runs (`a[@]` → `1 2 3`), plus a regression test for the non-leading and `eval` cases.

- [ ] **Step 2: Run, verify fail** (leading case) **and pass** (regression cases).

- [ ] **Step 3: Investigate + implement.** The bug: when `maybe_expand_command_alias` re-drives to scan the injected body's leading command word, a leading `name=(…)` does not emit the `ArrayOpen` signal (so the `(` surfaces as a bare `Op(LParen)` after `Lit "name="` → `UnsupportedCommand` at parser.rs:3143). Instrument the re-drive (`fill_to`/first-atom scan) to find where `try_scan_assign_prefix`'s array `(`-probe is bypassed or its `ArrayOpen` is dropped for the leading body word, and route the leading body word through the same assignment-prefix + `ArrayOpen` path a normal command word uses. Constraints:
  - Leading `name=(…)` AND `name+=(…)` in an alias body both work.
  - Non-leading array assignments in an alias body keep working.
  - `eval "a=(…)"` keeps working.
  - A leading scalar assignment in an alias body (`alias f='x=5; echo $x'`) keeps working.

- [ ] **Step 4: Run tests + hand-check.**
