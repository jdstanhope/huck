```
${x:+ ""}          bash n=1:<>   huck n=0    (FIX)
${x:+"$e" "$e"""}  bash n=2:<><> huck n=0    (FIX)
${x:+""}           bash n=1:<>   huck n=1:<> (KEEP)
${x:+"$e""$e"""}   bash n=1:<>   huck n=1:<> (KEEP)
${x:+''}           bash n=1:<>   huck n=1:<> (KEEP)
```

Add tests asserting the field COUNT and values for these via the public expansion API (model on the existing `use_alternate_*` tests; if they operate below field-splitting, add an engine-level test that runs `set -- ${x:+ ""}` through the executor and checks `$#`).

- [ ] **Step 2: Run, verify the two FIX cases fail + KEEP cases pass.**

- [ ] **Step 3: Investigate + implement.** The `UseAlternate` unquoted arm returns `Fields(expand(word, shell))`. Trace why `expand(word)` drops the quoted-empty field when the alternate word has internal IFS whitespace (`${x:+ ""}` → leading space splits, the trailing `""` quoted-empty field must survive; `${x:+"$e" "$e"""}` → two quoted-empty fields separated by a space). The bug is quoted-empty-field preservation across IFS field-splitting inside the alternate word. Fix so a quoted-empty segment produces an empty field even when adjacent to IFS whitespace, matching bash. Constraints (verify EACH vs bash with the arg-counter):
  - `${x:+ ""}`→n=1; `${x:+"" }`→n=1; `${x:+"$e" "$e"""}`→n=2; `${x:+"$e""$e" ""}`→bash count; `${x:+ "$e""$e"""}`→bash count.
  - KEEP: `${x:+""}`→1, `${x:+"$e""$e"""}`→1, `${x:+''}`→1, `${x:+ ''}`→bash count.
  - Regression: a plain unquoted split still works (`a="x  y"; set -- $a; echo $#`→2); a top-level `set -- a "" b` stays 3.
  - Also check the `${x:-word}` (default) form behaves identically (same arm).
