# lastpipe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement bash `lastpipe` — run the last stage of a multi-stage foreground pipeline in the current shell (not a fork) when `shopt -s lastpipe` is set and job control is off — flipping the `lastpipe` bash-suite category to PASS (Summary PASS 25→26, FAIL 57→56).

**Architecture:** All in `crates/huck-engine/src/executor.rs`. huck forks every pipeline stage via `spawn_pipeline`; `run_multi_stage` waits them and sets `PIPESTATUS`. lastpipe adds a `PipelineStage::InProcess { stdin_fd }` variant: the last stage is not forked; `run_multi_stage` runs it in the parent (via `RedirectScope` fd-0 swap + `run_command`) BEFORE reaping the forked stages, then assembles `PIPESTATUS` and propagates the stage's control-flow outcome.

**Tech Stack:** Rust (crate `huck-engine`); bash-diff harnesses; the official bash test-suite runner.

Issue: [#306](https://github.com/jdstanhope/huck/issues/306). Spec: `docs/superpowers/specs/2026-07-26-lastpipe-design.md`.

### Task 2: The lastpipe execution branch

**Files:**
- Modify: `crates/huck-engine/src/executor.rs` (`spawn_pipeline` gate + last-stage InProcess; `run_multi_stage` in-process run + PIPESTATUS + outcome)
- Test: `tests/scripts/lastpipe_diff_check.sh` (new)

**Interfaces:**
- Consumes: `PipelineStage::InProcess`, `wait_pipeline_raw`'s `inprocess_status` (Task 1); `RedirectScope::redirect`; `run_command`; `shell.set_pipestatus`.
- Produces: end-to-end lastpipe behavior.

**Background:** Under the gate `mode == Foreground && shopt("lastpipe") && !job_control_active() && matches!(sink, StdoutSink::Terminal)`, the last stage is not forked. `spawn_pipeline` records its resolved stdin fd as `InProcess { stdin_fd }` and preserves that fd from the parent bulk-close. `run_multi_stage` runs the in-process stage BEFORE `wait_pipeline_raw` (running after would deadlock: the forked upstream stages would block writing to a full pipe with no reader).

- [ ] **Step 1: Write the failing harness**

Create `tests/scripts/lastpipe_diff_check.sh` (model on an existing `checkf label 'body'` harness like `pipefail_diff_check.sh` if present, else `tilde_diff_check.sh`), byte-identical bash↔huck incl. stderr + exit. Each fragment sets `shopt -s lastpipe` (and the persistence ones run at top level = Terminal). Cover:

```
# variable persistence
shopt -s lastpipe; echo a b c | read foo; echo "foo=$foo"                       # a b c
shopt -s lastpipe; tot=0; printf '%d\n' 1 2 3 | while read n; do tot=$((tot+n)); done; echo $tot  # 6
shopt -s lastpipe; unset bar; echo g h i | bar=7; echo "bar=$bar"               # 7
shopt -s lastpipe; last=; printf '%s\n' a b c | while read x; do last=$x; done; echo "last=$last"  # c
# exit status / PIPESTATUS / pipefail
shopt -s lastpipe; exit 3 | false; echo "$? -- ${PIPESTATUS[@]}"                # 1 -- 3 1
shopt -s lastpipe; true | true | false; echo "$? -- ${PIPESTATUS[@]}"           # 1 -- 0 0 1
shopt -s lastpipe; set -o pipefail; true | false | true; echo "$? -- ${PIPESTATUS[@]}"  # 1 -- 0 1 0
# function last stage + return
shopt -s lastpipe; f() { cat | read v; return 42; }; echo HI | f; echo "$v -- $? -- ${PIPESTATUS[@]}"  # HI -- 42 -- 0 42
# nested lastpipe
shopt -s lastpipe; printf 'A\nB\n' | while read L; do printf '1\n2\n' | while read D; do echo $L$D; done; done  # A1 A2 B1 B2
# closed fd 0
shopt -s lastpipe; exec 0<&-; echo x | read x; echo "x=$x"                      # x
shopt -s lastpipe; echo y | cat | read y; echo "y=$y"                           # y (3-stage)
# negative controls
echo a b c | read foo; echo "off:$foo"                                          # off:   (lastpipe OFF → forked → empty)
shopt -s lastpipe; echo "cap:$(echo a b c | read z; echo "[$z]")"               # bash: cap:[a b c] (subshell); see NOTE
```

For `exit N | exit M` (shell-exit) use a SEPARATE check that runs a whole script via `bash -c '…'` vs `huck -c '…'` and compares `$?` of the shell, e.g. body `shopt -s lastpipe; exit 5 | exit 9; echo NOTREACHED` and assert the *process* exit code is 9 and `NOTREACHED` is not printed.

NOTE on the capture case: inside `$()` the Terminal gate suppresses lastpipe, but bash runs the `$()` in a subshell where `read z` DOES persist within that subshell — so bash prints `[a b c]` and huck (suppressed) prints `[]`. If that fragment diverges, DROP it from the harness (capture-context lastpipe is an explicit follow-up, issue to be filed) and instead assert the top-level (Terminal) behavior only. Verify each fragment against real bash before locking the expected values.

- [ ] **Step 3: Gate + `spawn_pipeline` produces `InProcess` for the last stage**

Compute the gate once (in `spawn_pipeline`, after `job_control`/`interactive` are known):
```rust
let lastpipe = mode == SpawnMode::Foreground
    && shell.shopt_options.get("lastpipe").unwrap_or(false)
    && !shell.job_control_active()

```
In the stage loop, when `is_last && lastpipe`: build the last stage's stdin fd exactly as today (the resolved `stdin` `ChildFd` — pipe read end, or an explicit `<`/heredoc/herestr override), but instead of constructing `child_stdio` and spawning, take the raw fd OUT of the `ChildFd` WITHOUT closing it (use the `ChildFd` ownership API — e.g. `into_raw()`/`std::mem::forget` equivalent; find how `ChildFd` exposes its raw fd and how to take ownership without Drop closing it), and:
```rust
stages.push(PipelineStage::InProcess { stdin_fd });
```
Then ensure `stdin_fd` survives the parent bulk-close (~7315-7328): add it to the same preserve condition as `capture_read_fd`/`capture_err_read_fd` (both the `close` guard and the `parent_held.retain`). The last stage's stdout under the Terminal gate is `Inherit` (no raw fd) — nothing to wire. Do NOT push to `live_pids_arc` (no pid) and do NOT set `first_pid` for the in-process stage.

Edge cases to preserve: if `is_last && lastpipe` but the last stage's stdin resolution FAILED (`redirect_failed`), fall back to the existing forked failed-stage path (do not go in-process). Keep `restore_inline_assignments(snap, shell)` on the in-process path too (it runs after each stage today).

- [ ] **Step 4: `run_multi_stage` runs the in-process stage BEFORE the wait; assemble**

After `spawn_pipeline` returns (and after the `stage_pids` reconstruction), BEFORE the capture-drain/`wait_pipeline_raw` block, detect an `InProcess` last stage and run it:
```rust
let inproc: Option<ExecOutcome> = if let Some(PipelineStage::InProcess { stdin_fd }) = stages.last().copied() {
    let mut scope = RedirectScope::new();
    // dup the pipe read end onto fd 0 for the last stage; handles a closed fd 0.
    if scope.redirect(shell, stdin_fd, libc::STDIN_FILENO, sink, err_sink).is_ok() {
        let outcome = run_command(&commands[commands.len() - 1], shell, sink, err_sink);
        drop(scope);                          // restores fd 0
        unsafe { libc::close(stdin_fd); }
        Some(outcome)
    } else {
        unsafe { libc::close(stdin_fd); }
        Some(ExecOutcome::Continue(1))
    }
} else { None };
let inproc_status = inproc.as_ref().map(outcome_status);   // extract exit status (see below)
```
Where `outcome_status(&ExecOutcome) -> i32` maps the actual variants (`builtins.rs:26`): `Continue(s) => s`, `Exit(s) => s`, `FunctionReturn(s) => s`, `LoopBreak(_, s) => s`, `LoopContinue(_) => 0`, `Interrupted(_) => 130`. This status goes into `PIPESTATUS` for the in-process slot. Use `ChildFd::into_raw()` (child_fd.rs:94) to take the stdin fd out of the resolved `ChildFd` without closing it in Task 2 Step 3.

Pass `inproc_status` to `wait_pipeline_raw(...)`. Under the Terminal/non-interactive gate the capture-drain block and terminal-handoff are already no-ops (no capture fds, `interactive == false`). Keep the `set_pipestatus` + pipefail/last-stage block as-is (it now includes the in-process status in the `AllExited` vector).

Finally, propagate control flow: if `inproc` is a non-`Continue` outcome, return it instead of `ExecOutcome::Continue(status)`:
```rust
if let Some(o) = inproc {
    if !matches!(o, ExecOutcome::Continue(_)) {
        drain_procsubs(shell, procsub_base);
        return o;   // exit 14 exits the shell (lastpipe1); return 42 from a fn last stage
    }
}
```
(Place this after `set_pipestatus` so `${PIPESTATUS[@]}` is still set when the outcome is a plain `Continue` — for the control-flow case, PIPESTATUS is also already written above.)
