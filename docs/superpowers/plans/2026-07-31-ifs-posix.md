## bash's exact last-field rule (verified vs bash 5.2.21)

After the first `n-1` variables consume their fields, for the LAST variable with
`rest` = unconsumed remainder:
1. `rest` empty → last var = `""`.
2. else extract ONE word `W` (skip leading IFS-ws, accumulate non-IFS, consume
   the separator run) leaving position `p`:
   - `p` at end → last var = `W` (trailing delimiter dropped).
   - else → last var = raw `rest` with trailing IFS-**whitespace** stripped
     (interior/extra trailing non-ws delimiters kept).

Truth table (all confirmed against real bash; use verbatim as tests):

| IFS | input | read vars | result |
|-----|-------|-----------|--------|
| `:` | `a:b:` | x y | `[a][b]` |
| `:` | `a:b::` | x y | `[a][b::]` |
| `:` | `a:b:c:` | x y | `[a][b:c:]` |
| `:` | `a::` | x y | `[a][]` |
| `:` | `a:::` | x y | `[a][::]` |
| `:` | `:::` | x y | `[][::]` |
| `: ` | `a:b: ` | x y | `[a][b]` |
| `: ` | `a: :b` | x y | `[a][:b]` |
| `:` | `a: :b` | x y | `[a][ :b]` |
| `:` | `:a:b:` | x y z | `[][a][b]` |
| `:` | `a:b::` | x y z | `[a][b][]` |
| `:` | `a:::` | x y z | `[a][][]` |
| ` :` | `a  b  c` | x y | `[a][b  c]` |
| `: ` | `::` | x y | `[][]` |
| `: ` | `:a:` | x y | `[][a]` |

### Task 1: Port bash's last-field splitter into `split_into_names`

**Files:**
- Modify: `crates/huck-engine/src/builtins.rs` — `split_into_names()` (~2904),
  the final "last field" block; add a small `next_word` helper.
- Test: `crates/huck-engine/src/builtins/read_tests.rs`.

**Interfaces:**
- Consumes: nothing new.
- Produces: `split_into_names(line, names, ifs) -> Vec<(String,String)>`
  (signature unchanged; only the last-variable value changes).

**Context the implementer needs:**
- The per-field loop in `split_into_names` (before the "Pad missing fields"
  step) already extracts a word then consumes the separator run: for a non-ws
  IFS byte, consume exactly one + trailing ws-IFS; for a ws-IFS run, consume the
  whole run + optionally one non-ws-IFS + trailing ws. `split_read_fields`
  (~3015) uses the identical separator logic — this is huck's
  `get_word_from_string` equivalent.
- Factor that "accumulate one word + consume its separator run" into a helper
  `fn next_word(bytes: &[u8], mut i: usize, is_ws, is_nonws, is_any) ->
  (String, usize)` that returns the word text and the position AFTER the
  separator run, and use it BOTH in the loop and in the new last-field block, so
  they provably agree. (Leading-IFS-whitespace skipping stays where it is — the
  up-front skip before the loop, and after each separator run; do not double-skip.)
- The `names.len() == 1` branch and the empty-IFS branch are correct — do NOT
  change them.

- [ ] **Step 1: Failing tests.** Rewrite `split_last_field_strips_only_ws_ifs`
  (it asserts the OLD divergent behavior) to the bash-correct values and rename
  it (e.g. `split_last_field_readdef_rule`). Add `split_into_names` unit cases
  for every truth-table row above (drive them through `split_into_names` with
  the right `ifs` and `names`). Example (colon IFS):

```rust
let n = |v: &[&str]| v.iter().map(|s| s.to_string()).collect::<Vec<_>>();
let vals = |s: &str, names: &[&str], ifs: &str| {
    split_into_names(s, &n(names), ifs).into_iter().map(|(_, v)| v).collect::<Vec<_>>()
};
assert_eq!(vals("a:b:", &["x","y"], ":"), vec!["a", "b"]);      // strip sole trailing
assert_eq!(vals("a:b::", &["x","y"], ":"), vec!["a", "b::"]);   // keep double trailing
assert_eq!(vals("a:b:c:", &["x","y"], ":"), vec!["a", "b:c:"]); // keep after interior
assert_eq!(vals("a::", &["x","y"], ":"), vec!["a", ""]);        // empty last, delim dropped
assert_eq!(vals(":a:b:", &["x","y","z"], ":"), vec!["", "a", "b"]);
assert_eq!(vals("a:b: ", &["x","y"], ": "), vec!["a", "b"]);    // mixed IFS trailing
assert_eq!(vals("a: :b", &["x","y"], ": "), vec!["a", ":b"]);
assert_eq!(vals("a  b  c", &["x","y"], " :"), vec!["a", "b  c"]);
```
